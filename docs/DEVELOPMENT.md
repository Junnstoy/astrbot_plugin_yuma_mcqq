# 设计决策与开发记录

当前版本 1.4.1，配置 schema 4；以下保留各版本实施历史，当前接口以 [模块约定](IMPLEMENTATION_CONTRACT.md) 为准。

## 需求基线

本次以用户确认的新设计为准：Paper、官方 QueQiao、NapCat/OneBot、原版 MC 客户端。旧插件只做数据迁移，不移植旧指令或玩法，不依赖其他 AstrBot 插件。

| 用户确认 | 实现选择 |
| --- | --- |
| QQ与MC互相唯一，换绑有CD，验证码可选 | 默认名称身份，QQ/名称忽略大小写唯一；验证后增加真实 UUID 唯一约束，冷却覆盖 QQ/名称/已知 UUID |
| 名称是“签到”，先游戏后群 | signin click 回包识别后才进入群签到事务；游戏与群各自成功/重复组成四种回复，游戏重复也可补齐群签到 |
| 每日允许签到时段、日期奖励活动 | 时段限制整个命令；路由当地日期匹配单个最高优先级活动，倍率或范围二选一，抽样与规则快照随操作保存 |
| 群积分只在商店兑换，名称可改 | 一套账户/账本，`points_name` 控制文案，不增加游戏货币兑换系统 |
| 很多自定义指令，每条独立模板 | 稳定action ID、独立参数/规则/模板，共用清洗器 |
| GUI、管理行为改名、UMO、可选独立前缀 | Plugin View和鉴权API、稳定命令注册、`command_prefix` 过滤、异步保留原始UMO |
| `mc帮助` 只发一张图，每列最多 15 条命令 | 按全局帮助顺序逐列纵排，超出自动新列，标题不计数；连续分类块使用矩形，跨列或被打断后标“续”；超出渲染尺寸或缺字体时回退完整文字 |
| 图片、语音、视频、文件、合并、引用和表情 | 优先用公开源链接；原版点击/悬浮，引用位置/悬浮模板与九类组件颜色可配，无需ChatImage |
| AI优先于普通转发 | 显式指令 → AI唤醒/接管判断 → 低优先级普通转发 |
| TPS、MSPT、ping、图片与GUI | 文本命令返回实际RCON；独立性能图和间隔采样；玩家延迟和机器人RTT分开，不把缺失填零 |
| 正向/反向连接，鉴权名与显示名分开 | forward主动连服，reverse接收QueQiao带token连接；`display_name`不改变`name`鉴权 |
| 旧插件只迁数据，可选择迁入名称绑定 | 源文件与绑定计划分别校验，预览目标服和冲突；已有账本可补绑定，不重复入账或恢复后来主动解除的绑定 |

## 1.0 实施记录（2026-10-31）

1. 检查目标仓库及其分支流程，创建 `feat/session-checkin`。检查已安装的 AstrBot 4.29 框架接口；没有读取生产配置、密钥或运行数据库。
2. 以新接口约定拆分框架适配、业务存储、网关/富消息/采样三个模块组，并完成 Application 组合入口、GUI 和配置。
3. 从旧积分插件的表定义确定显式迁移格式；不导入旧插件运行代码。迁移保留期初余额、历史、已用码和原奖励快照；旧名字绑定仅归档。
4. 根据提供的两种实际 LiteSignIn 回包实现清洗、玩家匹配和状态识别；多义/未知/跨日回包不发点数。
5. 检查 QueQiao 官方协议及 RCON 源码，修正“接口失败不等于游戏未执行”。已发送的错误/超时保留 UNKNOWN，禁止自动重放或退款。
6. 使用真实 AstrBot 4.29 的注册器和命令配置存储做隔离测试，验证改名、别名、停用、权限、重载和GUI认证；所有框架数据目录指向测试目录。
7. 补齐配置事务回滚、取消后清理、数据库关闭前处理在途请求、绑定版本单调增长、冻结点数并发防透支和共享scope策略一致性。
8. 用真实 Edge、合成 Bridge 和合成业务数据验收7页GUI、命令表单、回包预览和移动端。修正普通HTTP环境随机ID兼容及曲线时间轴。
9. 汇总完整拓扑、规则、部署、迁移与验证记录；源代码、测试、文档、合成截图提交到目标仓库分支并通过PR交付。

## 1.1 反馈修订（2026-10-31）

按用户八项反馈调整现有实现；对应现象、修复和管理员操作集中记录在 [UPGRADE_1_1.md](UPGRADE_1_1.md)。旧仓库与参考插件用于对照用户需要的交互和消息行为，不构成新运行时依赖。

- 名称绑定与真实 UUID 分开存储。未验证身份不制造离线 UUID；同名补充验证保留剩余冷却并增加版本，老库真实 UUID 在事务中升级。余额、流水和外部订单不重建。
- 成功、群已签、游戏错误三种回复分开处理。识别用的去前缀文本与用于展示的完整 `{rcon}` 分开，货币名和回包随操作持久化，恢复时不丢原内容。
- 连接方向作为服务器配置，反向接入校验名称及 Bearer token。服务器显示文字独立保存，避免编辑展示名称导致协议鉴权变化。
- 文本性能查询、连接状态和历史图片分成独立动作；新增 `performance` 稳定动作，不替换已有动作 ID。
- 转发修复围绕消息链、引用作者、颜色状态、公开媒体链接及无消息 ID 的游戏通知展开。服务不承担 ChatImage 客户端图片渲染。
- GUI 将常用选项表单化，类型与事件采用复选框，复杂签到规则收在高级区；模拟回包与真正执行 RCON 使用不同入口。
- 新增字段用兼容默认值合并已有配置；旧路由保留原模板，启用文本转发的旧配置增加表情类型。命令管理覆盖继续通过稳定处理器 ID 保留。
- 回归验证使用临时 SQLite、模拟 RCON/OneBot/QueQiao，以及隔离 AstrBot 和浏览器环境，不读取生产账户数据或真实迁移余额。当前验证结果以 [VALIDATION.md](VALIDATION.md) 为准。

## 1.1.1 修订记录（2026-10-31）

管理页面解绑原先默认检查普通成员 CD，现与管理员聊天代操作共用明确的管理路径；绑定唯一性、历史、版本和后续普通成员 CD 保留，旧验证码在成功管理操作后作废。新增 `cmd` 使用当前群服务器并复用持久执行记录，保留 JSON 命令字面值和未知结果不重放约束。真实框架的 GreedyStr 会先归一化空白，因此只对成功匹配的 `cmd` 入口保留原始参数尾部，其余管理行为匹配与权限不变。TPS/ping 默认值统一为 `tps`/`ping`，配置 v3 精确迁移旧默认并保留其他自定义值。

管理行为 400 经官方 AstrBot 4.29.1、真实管理 API、实际部署模块路径和前端请求格式测试后，用户提供响应并确认“在线人数”被旧鹊桥插件占用。此项记为配置冲突，保留框架的名称与别名冲突检查；未更改生产旧插件。验证使用隔离的真实框架接口、临时数据库与 GUI 合成配置，详见验证记录。

## 1.2.0 修订记录（2026-10-31）

- 签到按本次游戏状态和本日群结算独立显示四种组合。每条新请求仍游戏先行；群重复不覆盖当前游戏成功或连续天数，同消息重放和恢复使用各自已保存的结果。未知或失败回包不发群点数，也不伪称已签到。
- `group_result/game_result/days` 加入签到模板变量。默认展示玩家、群结果、游戏结果三行；保留原 `rcon` 等变量，旧已存成功结果缺失天数时不补造数值。纯预览复用业务渲染，支持当前路由、模拟群签到开关、奖励和最终余额，不查询真实账户、不写库或发 RCON。
- QQ → MC 默认前缀加入 `{reply}`，引用标记可放在发送者旁；悬浮模板支持发送者、摘要和时间。九类富消息组件颜色独立配置，接受 Minecraft 16 色名称或 `#RRGGBB`，引用和媒体仍服务于原版客户端。
- 配置 schema 升至 4：只替换精确匹配的旧官方前缀，并删除精确匹配的旧官方签到回复覆盖以使用新默认。其他自定义内容保留；业务数据库身份 schema 仍为 2，已有账本与签到记录不因配置迁移重建。
- 旧数据迁移新增绑定选择和目标服务器计划。预览返回源文件 `digest` 与 `plan_digest`；管理员确认选中来源、目标服和冲突后再提交。有选中绑定时校验计划摘要，GUI 始终携带两个摘要及确认标记；保留 `binding_choices=[]` 的旧账本专用调用兼容方式。
- 旧名称以未验证身份导入，不制造 UUID、不覆盖现有归属。已导入账本可以补迁绑定而不重复余额或流水；已完成来源键保留，后续用户主动解绑或改绑不会因重复导入被恢复。历史 1.0 的“旧名字绑定仅归档”行为由此扩展，原始归档仍保留。
- 验证沿用隔离临时 SQLite、模拟网关与浏览器数据。测试范围和结果统一见 [验证记录](VALIDATION.md)，不据此宣称真实服务器端到端联调或生产旧库导入已完成。

## 1.3.0 修订记录（2026-10-31）

- 引用标签、配色、悬浮三项独立设置。`templates.reply_label` 只插值原作者 `{sender}`，不会把作者文本作为颜色或二次模板执行。
- 绑定和诊断列表改为受限 SQL 分页，包含总数、稳定排序和作用域过滤；较长迁移预览及帮助表也分页。
- 在官方 4.29.1 同样的 iframe sandbox 中复现原生 confirm 被拒，解绑请求数为零；页面内 HTML dialog 修复后覆盖取消、失败重试和成功刷新。
- 服务器 ID 使用专门重命名动作。持久 journal 与逐库操作标记支持前向恢复，配置和命令注册回滚与重命名共用主入口锁。在途请求先排空，未知游戏交付不自动重放；执行入口重新取当前路由，避免旧上下文重新写回旧 ID。
- 图表添加纵轴，MSPT 仅显示时按 50 ms 换算 ticks；历史采样和聊天查询原值保留。
- 帮助图片/文字共用有效命令名、说明、显隐和排序；帮助编辑使用稳定动作 ID，与管理行为改名及实际启停分开。

## 1.4.0 修订记录（2026-10-31）

- 每日时段限制整条签到命令，先按路由时区检查是否允许，再进入绑定校验、抽样与游戏请求。支持跨午夜时段；签到日仍按当地自然日计算。
- 日期活动支持倍率和范围两种模式；最高优先级单活动生效，同优先级重叠拒绝。Decimal 计算倍率并向下取整，抽样及活动快照持久化；恢复和重放使用原结果，不随当前活动变化重新抽样。
- GUI 为每日时段和活动提供独立表单、增删改/启停/优先级、纯预览。同作用域路由共享规则，预览复用纯策略函数，不接触账户、RCON 或随机数。
- 帮助图只生成并发送一张图片，严格按全局顺序每列纵排最多 15 条命令，超出自动新列；分类标题不计数，普通字号不缩。连续的同类内容用矩形框住，跨列或中间插入其他分类后标“续”；全局编号与实际位置一致。帮助默认排第一，已有显式排序覆盖保留。GUI 数据表和帮助编辑表的分页保持原有行为。
- 图片与文字继续使用同一份经过权限和显示设置过滤的帮助文档。现有 `help.image_enabled`、说明、隐藏和排序配置直接沿用，管理行为名称、别名与实际启停不变。
- 超过渲染尺寸上限、缺少中文字体或图片生成失败时回退完整文字，不截断条目、不自动拆图。插件不联网下载字体；系统中文字体要求沿用原部署规则。
- [单图帮助样张](screenshots/help-example.png)及 5 / 15 / 30 / 50 条自定义指令预览只使用合成配置，均另含 23 个默认指令，对应 2 / 3 / 4 / 5 列。样张帮助排第一、首条自定义排第三，用于核对插入位置和跨分类续接。版本说明见 [UPGRADE_1_4.md](UPGRADE_1_4.md)，具体测试范围以 [验证记录](VALIDATION.md) 为准。
- 用户已确认最终排版，并要求移除图内使用说明中的“排版预览/排序测试”及“按序号……每列最多 15 条”等提示。帮助图片保留实际命令和使用说明，测试用途与排版规则记录在文档及场景报告中。代码、合成预览和验证记录随 1.4.0 提交；尚未进行真实 QQ/Paper 验收。

## 1.4.1 修订记录（2026-11-01）

- 点数排行固定取当前作用域总余额前 10 名，保留冻结点数和原同分次序。一次查询关联当前绑定名；换绑显示新名，解绑或未绑定显示“未绑定玩家”，不向群回复 QQ 号，也不使用历史绑定推断当前身份。
- 原始消息与框架消息合并时保留对应媒体段已有的有效 URL，避免原始文件 ID 或空字段覆盖后多做一次 `get_image`；来源识别补充 `file_path` 中的 HTTP(S) 地址。已有公开地址仍直接转发，本地路径与 Base64 仍走原缓存规则。
- 当前层媒体来源和引用元信息以最多 4 个任务并行准备，实际渲染、缓存发布及最终广播保持原顺序。遇合并节点停止前向预取，继续遵守嵌套预算；取消时清理未完成任务。来源地址限制、可信本地路径和引用同会话验证保留。
- 增加 `QQ-to-MC slow` 阶段日志：单阶段达到 1 秒时记录 WARNING，同一阶段每 30 秒最多一条，仅含阶段名和耗时。`render` 是包含查询/缓存等工作的聚合耗时，不能把它与子阶段简单相加；生产定位步骤见升级说明。
- 源码核对确认官方 AstrBot 4.29.1 会在插件前逐张本地化正文及引用图片，远程图片会经历前置下载；群聊上下文自动理解启用并指定模型时，普通图片还可能先等待逐图模型转述。关闭“自动理解图片”只避免该转述路径，不关闭图片预处理，本插件未调整框架或优先级。
- 新增 `framework_wait`，从有效 `event.created_at` 估算平台适配完成后到本插件入口的等待，涵盖队列、预处理和前序处理器；不包含 NapCat/适配阶段，且会受系统时钟调整影响。它与其他慢阶段日志一起用于缩小排查范围，不能单独证明延迟原因。
- 图片标签出现慢的排查与修复以转发各阶段为界；已有公网媒体地址本来就不下载，不据此把所有延迟归因于图片下载。没有生产日志和真实 QQ/Paper 联调数据，不能确认用户实服的具体慢点；验证结果与定位方法见 [验证记录](VALIDATION.md) 和 [1.4 系列升级说明](UPGRADE_1_4.md)。

## 取舍与边界

- 外部命令与数据库不能原子提交。用已发送/已确认/未知等持久状态约束自动行为；不会宣称网络超时后仍可保证恰好执行一次。
- 商店目前单件订单，不增加未要求的批量购买、补签重置或插件互相调用。签到时段和日期奖励是新实现的显式配置，不导入旧插件的执行逻辑。可选独立前缀只作用于本插件的实际命令过滤，继续使用 AstrBot 命令管理与权限。
- 目标服务器记入绑定。多群可共享点数scope，但游戏签到与游戏商品要求绑定服务器一致；跨服身份域扩展需单独设计。免验证名称绑定表示声明玩家名，真实游戏账号控制权只能由验证模式证明。
- 管理GUI使用AstrBot认证，媒体服务只开放随机限时资源。公开快照、日志和截图不包含凭据或私聊奖励。
- 动态命令注册适配AstrBot 4.29内部接口，版本升级需运行框架集成测试。媒体格式和服务器组件版本在实服确认。
- 未执行生产部署、真实余额迁移、真实奖励发放或机器人消息发送。实际端到端联调列为部署验收，不混同于已通过的模拟/框架测试。

具体测试证据见 [VALIDATION.md](VALIDATION.md)，实际接口边界见 [IMPLEMENTATION_CONTRACT.md](IMPLEMENTATION_CONTRACT.md)。
