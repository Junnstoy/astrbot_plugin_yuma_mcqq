# 设计决策与开发记录

## 需求基线

本次以用户确认的新设计为准：Paper、官方 QueQiao、NapCat/OneBot、原版 MC 客户端。旧插件只做数据迁移，不移植旧指令或玩法，不依赖其他 AstrBot 插件。

| 用户确认 | 实现选择 |
| --- | --- |
| QQ与MC互相唯一，换绑有CD，验证码可选 | 默认名称身份，QQ/名称忽略大小写唯一；验证后增加真实 UUID 唯一约束，冷却覆盖 QQ/名称/已知 UUID |
| 名称是“签到”，先游戏后群 | signin click 回包识别后才进入群签到事务；重复游戏签到也可补齐群签到 |
| 群积分只在商店兑换，名称可改 | 一套账户/账本，`points_name` 控制文案，不增加游戏货币兑换系统 |
| 很多自定义指令，每条独立模板 | 稳定action ID、独立参数/规则/模板，共用清洗器 |
| GUI、管理行为改名、UMO、可选独立前缀 | Plugin View和鉴权API、稳定命令注册、`command_prefix` 过滤、异步保留原始UMO |
| 图片、语音、视频、文件、合并、引用和表情 | 优先用公开源链接；缓存用于需转存的资源和记录页；原版点击/悬浮，无需ChatImage |
| AI优先于普通转发 | 显式指令 → AI唤醒/接管判断 → 低优先级普通转发 |
| TPS、MSPT、ping、图片与GUI | 文本命令返回实际RCON；独立性能图和间隔采样；玩家延迟和机器人RTT分开，不把缺失填零 |
| 正向/反向连接，鉴权名与显示名分开 | forward主动连服，reverse接收QueQiao带token连接；`display_name`不改变`name`鉴权 |

## 1.0 实施记录（2026-10-31）

1. 检查目标仓库及其分支流程，创建 `feat/session-checkin`。检查已安装的 AstrBot 4.29 框架接口；没有读取生产配置、密钥或运行数据库。
2. 以新接口约定拆分框架适配、业务存储、网关/富消息/采样三个模块组，并完成 Application 组合入口、GUI 和配置。
3. 从旧积分插件的表定义确定显式迁移格式；不导入旧插件运行代码。迁移保留期初余额、历史、已用码和原奖励快照；旧名字绑定仅归档。
4. 根据提供的两种实际 LiteSignIn 回包实现清洗、玩家匹配和状态识别；多义/未知/跨日回包不发点数。
5. 检查 QueQiao 官方协议及 RCON 源码，修正“接口失败不等于游戏未执行”。已发送的错误/超时保留 UNKNOWN，禁止自动重放或退款。
6. 使用真实 AstrBot 4.29 的注册器和命令配置存储做隔离测试，验证改名、别名、停用、权限、重载和GUI认证；所有框架数据目录指向测试目录。
7. 补齐配置事务回滚、取消后清理、数据库关闭前处理在途请求、绑定版本单调增长、冻结点数并发防透支和共享scope策略一致性。
8. 用真实 Edge、合成 Bridge 和合成业务数据验收7页GUI、命令表单、回包预览和移动端。修正普通HTTP环境随机ID兼容及曲线时间轴。
9. 汇总完整拓扑、规则、部署、迁移与验证记录；源代码、测试、文档、合成截图提交到目标仓库分支并通过PR交付。

## 1.1 反馈修订（2026-10-31）

按用户八项反馈调整现有实现；对应现象、修复和管理员操作集中记录在 [UPGRADE_1_1.md](UPGRADE_1_1.md)。旧仓库与参考插件用于对照用户需要的交互和消息行为，不构成新运行时依赖。

- 名称绑定与真实 UUID 分开存储。未验证身份不制造离线 UUID；同名补充验证保留剩余冷却并增加版本，老库真实 UUID 在事务中升级。余额、流水和外部订单不重建。
- 成功、群已签、游戏错误三种回复分开处理。识别用的去前缀文本与用于展示的完整 `{rcon}` 分开，货币名和回包随操作持久化，恢复时不丢原内容。
- 连接方向作为服务器配置，反向接入校验名称及 Bearer token。服务器显示文字独立保存，避免编辑展示名称导致协议鉴权变化。
- 文本性能查询、连接状态和历史图片分成独立动作；新增 `performance` 稳定动作，不替换已有动作 ID。
- 转发修复围绕消息链、引用作者、颜色状态、公开媒体链接及无消息 ID 的游戏通知展开。服务不承担 ChatImage 客户端图片渲染。
- GUI 将常用选项表单化，类型与事件采用复选框，复杂签到规则收在高级区；模拟回包与真正执行 RCON 使用不同入口。
- 新增字段用兼容默认值合并已有配置；旧路由保留原模板，启用文本转发的旧配置增加表情类型。命令管理覆盖继续通过稳定处理器 ID 保留。
- 回归验证使用临时 SQLite、模拟 RCON/OneBot/QueQiao，以及隔离 AstrBot 和浏览器环境，不读取生产账户数据或真实迁移余额。当前验证结果以 [VALIDATION.md](VALIDATION.md) 为准。

## 取舍与边界

1.1.1 修订记录：管理页面解绑原先默认检查普通成员 CD，现与管理员聊天代操作共用明确的管理路径；绑定唯一性、历史、版本和后续普通成员 CD 保留，旧验证码在成功管理操作后作废。新增 `cmd` 使用当前群服务器并复用持久执行记录，保留 JSON 命令字面值和未知结果不重放约束。真实框架的 GreedyStr 会先归一化空白，因此只对成功匹配的 `cmd` 入口保留原始参数尾部，其余管理行为匹配与权限不变。TPS/ping 默认值统一为 `tps`/`ping`，配置 v3 精确迁移旧默认并保留其他自定义值。

管理行为 400 经官方 AstrBot 4.29.1、真实管理 API、实际部署模块路径和前端请求格式测试后，用户提供响应并确认“在线人数”被旧鹊桥插件占用。此项记为配置冲突，保留框架的名称与别名冲突检查；未更改生产旧插件。验证使用隔离的真实框架接口、临时数据库与 GUI 合成配置，详见验证记录。

- 外部命令与数据库不能原子提交。用已发送/已确认/未知等持久状态约束自动行为；不会宣称网络超时后仍可保证恰好执行一次。
- 商店目前单件订单，不增加未要求的批量购买、旧倍率、补签重置或插件互相调用。可选独立前缀只作用于本插件的实际命令过滤，继续使用 AstrBot 命令管理与权限。
- 目标服务器记入绑定。多群可共享点数scope，但游戏签到与游戏商品要求绑定服务器一致；跨服身份域扩展需单独设计。免验证名称绑定表示声明玩家名，真实游戏账号控制权只能由验证模式证明。
- 管理GUI使用AstrBot认证，媒体服务只开放随机限时资源。公开快照、日志和截图不包含凭据或私聊奖励。
- 动态命令注册适配AstrBot 4.29内部接口，版本升级需运行框架集成测试。媒体格式和服务器组件版本在实服确认。
- 未执行生产部署、真实余额迁移、真实奖励发放或机器人消息发送。实际端到端联调列为部署验收，不混同于已通过的模拟/框架测试。

具体测试证据见 [VALIDATION.md](VALIDATION.md)，实际接口边界见 [IMPLEMENTATION_CONTRACT.md](IMPLEMENTATION_CONTRACT.md)。
