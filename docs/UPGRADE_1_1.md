# 升级到 1.1.0

1.1 修订默认绑定、签到回复、富消息、连接方向与 GUI。继续使用原账户、流水、订单和命令稳定 ID；不会自动向 QQ 发送奖励、重新执行游戏交付或导入其他插件数据库。真实 QQ/Paper 环境仍需部署验收，模拟测试和框架测试不等于实际服已经通过验收。

## 八项反馈对应

| 用户反馈 | 1.1 行为与入口 |
| --- | --- |
| 1. 引用、颜色码，以及 QQ 表情/视频/图片/链接体验不完整 | QQ 引用展示回复作者及悬浮正文；颜色生成 Minecraft 组件；表情显示可悬浮的 `[表情]`；支持 `www.` 链接。图片、视频、语音和文件优先复用 QQ 公开源链接，不要求开启缓存，不依赖 ChatImage |
| 2. 绑定验证码应可关闭，默认不需要游戏操作 | 全局“游戏验证码验证”默认关闭；直接按玩家名绑定。开启后才要求游戏验证码。直接绑定不伪造 UUID，玩家名忽略大小写唯一；原真实 UUID 保留 |
| 3. 签到回复应简洁，成功含奖励/余额及 RCON，群重复用失败短句 | 首次群成功使用下面的默认模板；群今日已签到使用固定默认短句。游戏先行顺序不变，游戏已签也能结算首次群签到；真实错误不会冒充群重复 |
| 4. 签到前缀、规则、回复覆盖和 types 含义不清，游戏事件需要开关，死亡消息无效 | 路由表单拆分基础/高级配置，前缀与规则说明单独显示；成功与重复回复使用独立文本框；QQ 消息类型和游戏事件分别复选。死亡、加入、退出等空消息 ID 通知不再被当作同一条消息丢弃 |
| 5. MC → QQ 的服务名需要独立显示名称 | 服务器新增 `display_name`，转发 `{server}` 使用它；真实 QueQiao `name` 继续用于鉴权。显示名留空时回退到原名称 |
| 6. 增加正向/反向连接，调整服务器和转发管理体验 | 每台服务器可选正向主动连接或反向监听；反向配置监听地址、端口、路径及必填 token。GUI 按连接模式显示字段，服务器连接、转发选项与监控分别管理 |
| 7. 回包测试含义不清，tps/mspt/ping 应返回实际 RCON，status 只表示在线 | GUI 明确“模拟回复（不执行）”及样例余额；真正执行入口单独标记。`tps/mspt/ping` 返回实际查询文本，`服务器状态` 只返回在线/离线；新增“性能图”返回历史 PNG |
| 8. 插件独立前缀可选，货币名称应使用占位符 | 新增 `command_prefix`，留空用 AstrBot 唤醒，非空使用本插件前缀；`points_name` 默认点数，业务显示和回复模板可引用 `{points_name}` |

首次群签到成功的默认模板：

```text
签到成功✅️
本次获得 {points_delta}{points_name}，当前{points_name}：{balance}
{rcon}
```

群今日已签到的默认回复：`签到失败❌️ 今日已签到，请不要重复签到。`

`{rcon}` 保留 `[手记人偶]` 等插件前缀，仅去除颜色、控制字符和回包日志包装；识别规则使用另外一份去前缀文本。两种模板分别是 `route.templates.signin` 与 `route.templates.signin_already`。

## 更新前

1. 停止插件业务操作并等待在途请求结束。记录尚未核对的订单，不通过重发命令判断交付状态。
2. 停止插件后备份整个插件数据目录，或使用 SQLite 一致性 backup API 制作数据库副本。活跃 WAL 数据库不能只复制主 `.sqlite3` 文件。保留 `settings.json`、业务数据库、命令操作记录及其他状态文件。
3. 安装包含 1.1.0 的代码与依赖后再加载。不要在代码更新时删除原数据目录或重建账户。

## 配置兼容与新默认值

启动读取已有配置时补齐新字段，并在内存升级至 `schema_version: 2`；下一次成功保存配置时持久化。已有服务器、路由、奖励范围、管理员、商品和自定义回复不会被默认值覆盖。

| 配置字段 | 新默认值 | 升级后影响 |
| --- | --- | --- |
| `schema_version` | `2` | 配置结构版本，旧结构自动兼容读取 |
| `binding_verification_enabled` | `false` | 新绑定默认直接按玩家名完成；若要继续强制验证码，管理员显式开启 |
| `points_name` | `点数` | 只改显示，不兑换、重算或清空已有余额 |
| `command_prefix` | 空字符串 | 保持 AstrBot 唤醒规则；填 `mc` 后使用 `mc签到` 或 `mc 签到` 等命令 |
| `server.display_name` | 空字符串 | 显示回退到原 `name`，原连接鉴权不变 |
| `server.connection_mode` | `forward` | 原正向 WebSocket 继续使用已有 URL/token |
| `server.reverse_host` | `0.0.0.0` | 仅反向模式监听使用；这是监听地址，不是给 QueQiao 填写的远端地址 |
| `server.reverse_port` | `8081` | 反向监听端口，需按实际部署确保 QueQiao 能连通 |
| `server.reverse_path` | `/queqiao` | QueQiao 应连接机器人可达地址上的这个路径 |

反向连接必须有非空 token，QueQiao 端使用相同 token 与 `server_name`。可以在相同监听地址/端口接收不同名称的服务器，由鉴权名称和路径定位；显示名称不参与鉴权。实际 QueQiao 配置方式和部署边界见 [TRANSPORT.md](TRANSPORT.md)。

旧路由 `types` 如果已经包含 `text`，升级时会补入 `face`；如果不需要表情，保存时取消该复选框。已有其他选择保留。`types` 控制 QQ → MC 的消息组成，`events` 控制 MC → QQ 的游戏事件，方向开关依旧生效。

旧 `templates.signin` 覆盖会继续保留，所以升级后不一定自动看到新的简版成功文案。想恢复新默认时，在 GUI 清空对应回复覆盖再保存；直接编辑配置时删除相应键，避免将覆盖设成空字符串。重复群签到的新覆盖键是 `signin_already`。默认 LiteSignIn 输出保持 `signin_rules: []` 即可，只有回包文字变化时才需要高级规则。

命令管理已有名称、别名和启停通过稳定 action ID 保留。现在共有 22 个内置动作，新动作 `performance` 默认名为“性能图”。原来用于查询时间范围的 `tps 24` / `mspt 24` / `ping 24` 应改为 `性能图 24`；文本性能查询和 `服务器状态` 不带参数。服务器状态反映 QueQiao 连接是否在线，历史监控和实际查询分别有自己的结果。

## 绑定数据库升级

业务数据库内部身份结构升级至 v2；这不需要点击“旧数据迁移”。原有真实 UUID 仍为真实 UUID，自动加上 `identity=uuid:<UUID>`、`verified=true`，保留 QQ、玩家名、绑定版本、历史和冷却。新建免验证绑定使用 `identity=name:<忽略大小写的玩家名>`、`mc_uuid=null`、`verified=false`。

QQ 和玩家名各自唯一，已知真实 UUID 同样唯一；未验证名字不是实际游戏控制权证明。直接绑定同一已验证名字不丢失 UUID。以后打开验证开关，同一 QQ 可为同名未验证身份补充验证，绑定版本增加、原剩余冷却不重置，目标 UUID 的既有冷却仍需遵守。

升级为事务操作。如果历史记录中不同 QQ 使用了相同玩家名或有其他身份唯一性冲突，会拒绝升级并回滚该身份事务。保留备份，在原版本中解除冲突绑定后再更新；不能以覆盖 UUID 的方式绕过。已经解绑的老记录也保留对应名称冷却，防止通过新免验证模式绕过原有 CD。

余额、账本、签到历史、冻结点数、订单及已用码保持原数据，不因身份升级重新入账。其他旧积分插件数据库仍需显式“预览 → 摘要确认 → 导入”，其只有名字的旧绑定仅归档；用户重新绑定按当前验证开关执行。详见 [MIGRATION.md](MIGRATION.md)。

## 更新后检查与回退

- 在 GUI 核对服务器鉴权名、显示名和连接方向，确认路由 UMO 未变化；反向模式先验证 QueQiao 的名称/token/路径一致。
- 核对绑定验证开关、独立前缀、货币名称及两种签到模板，再检查余额和未完成订单。
- 使用模拟回复验证规则，但以真实服查询确认 RCON 配置。测试一次首次群签到和一次新的重复请求，检查仍先游戏、后群判断。
- 分别检查引用悬浮、QQ 表情、公开图片/视频链接、死亡通知及勾选关闭后的行为。源链接可能过期；缓存只有在确需转存或完整合并页面时才需启用。
- `tps/mspt/ping` 应显示清洗文本，`服务器状态` 应仅有在线/离线，`性能图` 与 GUI 显示历史。查询命令需适配实际安装的服务端插件。

回退时先停止插件、保存更新后数据和外部交付核对记录，再同时恢复原代码与更新前的一致性数据备份。仅降级代码而继续使用新身份结构不属于受支持的回退方式。备份恢复不会撤回已发送私聊或已执行游戏奖励，恢复后必须先核对未知交付，不自动补发。
