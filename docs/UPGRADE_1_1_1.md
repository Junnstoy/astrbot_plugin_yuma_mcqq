# 更新到 1.1.1

本次修订管理员绑定操作、管理页面解绑和默认查询命令，并新增管理员 `cmd`。已有余额、签到、商品及订单保持不变；业务数据库身份结构仍为 v2，不需要执行旧插件数据迁移。

## 管理行为改名 400

本次反馈中，AstrBot 4.29.1 将 `list` 改为“在线人数”时的实际响应是：`指令名 '在线人数' 已被其他指令占用。` 用户确认名称由当前旧鹊桥插件占用，因此属于名称冲突，并非本插件改名功能故障。

正式移除旧插件并重载、释放名称后再保存改名。测试期间也可选择没有被占用的名称。框架同时检查已有别名，停用的动作仍可能占用名称；不要通过绕过冲突检查让同名动作同时处理消息。本次没有修改运行中的旧插件。

## 管理员绑定操作

| 操作 | 普通成员 | 管理员代操作 |
| --- | --- | --- |
| 绑定 | `绑定 MC名` | `绑定 QQ号 MC名` |
| 修改绑定 | `修改绑定 新MC名` | `修改绑定 QQ号 新MC名` |
| 解绑 | `解绑` | `解绑 QQ号` |

这里列出默认指令名；管理行为修改后的名称仍然生效。管理员指 AstrBot 管理员或当前群服路由配置的管理员 QQ。管理员代操作、管理员使用普通语法操作自己、已登录管理页面中的“管理员解绑”均直接完成，不受绑定 CD 限制，不需要游戏验证码。

管理员仍不能占用另一个 QQ 已绑定的 MC 名称或 UUID；目标已绑定其他名字时应使用“修改绑定”。成功操作记录操作者、目标 QQ、历史与版本，并作废目标旧验证码。失败时保留原绑定及验证码。普通成员不能代操作他人，后续普通成员操作仍检查冷却，余额和签到记录不清除。

管理员只输入 `绑定 QQ号` 时会返回用法提示，需要同时提供 MC 名称。管理员绑定纯数字 MC 名时可用完整的 `绑定 自己的QQ号 数字MC名` 形式；普通成员单参数数字仍作为自己的 MC 名处理。

管理页面解绑使用相同业务路径，无需手工传入 `force`。成功后刷新绑定列表并显示结果，已知的“CD 内管理员解绑失败”已修复。

## 管理员 cmd

发送 `cmd cmi ping rincho`，实际 RCON 命令为 `cmi ping rincho`。作用于当前群服路由的服务器，管理员无需先绑定 MC 账号。返回给 QQ 的是清洗颜色等格式后的实际回包，不把一条“已收到回复”当作奖励交付成功证明。

`cmd` 与其他内置动作一样支持管理行为改名/启停及独立唤醒前缀，默认权限仍由插件再次核对。原始参数不经过模板替换或拆分重组，因此 `tellraw` JSON 中的引号、空格和花括号保持字面值。

一次只发送一条命令，遵守 RCON 的 1446 字节长度限制。同一消息重复投递复用持久记录；超时或重载后结果未知时不自动重发。没有可用于去重的消息标识时，插件拒绝执行并提示原因。

## TPS 与 ping

默认查询及定时采样使用 `tps`、`mspt`、`ping`。返回给 QQ 的仍是实际 RCON 文本，监控只有在收到可识别数值时才记录；例如 `ping` 只返回 `Pong!` 时，不会凭空产生延迟数据。

配置结构升级为 `schema_version: 3`。读取 v1/v2 旧配置时，精确等于原默认值 `spark tps` / `spark ping` 的查询分别迁移为 `tps` / `ping`；其他自定义命令保持原样。下一次成功保存配置持久化新版本。新版中手动改回 Spark 命令并保存后，后续加载不会再次替换。

更新后在服务器表单核对查询命令；若服务端没有对应命令，可填写实际插件提供的命令，未知回包按原文显示。
