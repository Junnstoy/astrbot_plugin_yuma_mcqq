# 更新到 1.2.0

本次更新提供旧绑定迁移、引用位置与颜色配置，以及独立显示群/游戏签到结果。更新前备份插件数据，保留现有数据目录；不需要删除账户或重新迁入余额。代码更新本身不会导入外部数据库，也不会发送游戏命令。

## 旧绑定可以迁移

诊断与迁移 → 预览迁移，选择旧数据库备份和绑定目标服务器。路径必须在运行 AstrBot 的机器上；远程部署时，浏览器所在电脑的本地路径不能直接被服务器读取。

预览会分别列出可导入、重复、已存在、已处理和冲突记录。相同 QQ、忽略大小写的 MC 名、目标服一致的重复记录会合并。遇到同 QQ 对应多个 MC 名、同 MC 名被多个 QQ 占用，点击“选择绑定 / 重新核对”，取消不保留的记录，再检查计划。不能自动从没有时间字段的旧表中推断哪个账号归属正确。

确认计划可以导入后，点击“导入备份”并确认。选定绑定迁为未验证的名称身份，`mc_uuid=null`，不伪造 UUID。目标已有相同绑定时保留其验证状态、UUID、版本及冷却；冲突不会覆盖。

如果同一份备份此前已经迁入过余额，本次会补迁尚未处理的绑定，原余额、签到和订单不会再次导入。需使用原先同一份一致性备份；源内容变化时必须重新预览。已处理标记独立于当前绑定，用户后来解绑后，重复迁移不会恢复已解绑记录。预览计划变化时需要重新核对。

全部取消绑定选择表示仅归档旧绑定，不建立可用绑定。不要通过删除迁移记录或清空账户绕过冲突。详细参数和数据对应见 [迁移说明](MIGRATION.md)。

## 引用位置、颜色与悬浮

在“连接与群服 → 编辑与开关”中，把 QQ → MC 显示前缀设置为：

```text
&e[{group}]&e{sender}{reply}&8:
```

`{reply}` 是带悬浮事件的引用标签，不是普通文字。没有引用或关闭引用类型时为空；使用插槽后不会再在正文重复显示。旧自定义前缀未包含它时仍保留原引用位置。重复写入插槽会在各位置显示同一引用，但只查询一次原消息。

同一表单的“消息标签颜色”可分别修改链接、图片、语音、视频、文件、合并消息、引用、表情和 @提及的颜色。色块选择后保存即可；颜色不会改变可点击链接和悬浮事件。

引用悬浮文本框支持直接回车换行，默认：

```text
{sender}
{message}
Date: {time}
```

这里的作者、内容、时间都来自被引用的原消息。时间按该群路由时区显示为 `HH:MM:SS`；没有原时间时显示“未知”，不会使用当前时间替代。颜色代码及跨会话引用隔离继续生效。

## 群签到与游戏签到分别显示

默认回复模板变为：

```text
玩家: {player}
{group_result}
{game_result}
```

| 群内状态 | 本次游戏回包 | 回复中的两种结果 |
| --- | --- | --- |
| 首次 | 成功 | 群成功并显示奖励/余额；游戏成功并显示连续天数 |
| 已签到 | 成功 | 群重复；游戏成功并显示本次连续天数 |
| 首次 | 已签到 | 群成功并显示奖励/余额；游戏重复 |
| 已签到 | 已签到 | 群重复；游戏重复 |

顺序仍是先执行游戏签到，识别成功或重复后才结算群签到。相同消息重放不会重新发点；游戏未知/失败不会假装“今日已签到”，也不会未经确认发放群奖励。重复群签到不会把当天旧游戏结果覆盖到本次回包上。

诊断页的“签到回包解析示例”可粘贴成功/重复回包，勾选“模拟：群内今日已经签到”，查看四种组合；不查询真实余额、不写库、不发送 RCON。玩家名必须与样本一致。

## 配置兼容

配置结构升级至 v4，业务身份结构仍为 v2。精确等于旧官方默认值的前缀会补入 `{reply}`；精确旧默认签到覆盖会移除以采用新模板。其他自定义前缀和回复覆盖保留：若希望采用新三行签到格式，可清空路由中的两个完整回复覆盖，或填写上面的三行模板。

真实源数据库仅做只读检查；仓库包含合成测试和合成 GUI 截图，不含用户数据库或个人记录。测试范围与实际部署验收见 [验证记录](VALIDATION.md)。
